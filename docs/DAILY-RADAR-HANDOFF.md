## 1. 接手与切换

1. **先只读核验。** 确认新 Dot 能读仓库、配置、历史与 GitHub Pages 工作流，能在云端运行 `npm run check`，并读到线上数据。先查看 `main` 和线上最新日期，不把本手册的快照当作实时状态，也不要接着发布未知候选。
2. **由用户确认写入授权、首跑日期和通知位置。** 不假定旧 Dot 的 GitHub 连接、任务、权限和本地候选会自动转移。发布范围仅为该公开仓库的项目所需代码、公开研究资料与素材；不上传秘密、个人信息或浏览器里的私人数据，不联系第三方、不购买服务。
3. **一个时段只保留一个发布者。** 建议新 Dot 先做一次只读试跑，报告选题、素材缺口和验证结果。新 Dot 就绪后，由用户指定切换日期，旧任务暂停后再启用新任务；不要双跑、重复发通知，也不要擅自删除旧任务。交付本手册时，旧任务没有变更。

## 2. 日报怎么选

| 频道 | 每期规则 | 筛选重点 |
| --- | --- | --- |
| **迅 `xun` · 蓝框** | **3 篇正式会议 + 2 篇正式期刊**，两类独立，不能互补；证据或质量不足时少推并说明。 | 先找近期、未推过的机器人学习与具身智能，保留其他高质量机器人方向，排除纯机构设计。Best Paper、Oral、Spotlight 优先但不代替质量；获奖、候选、提名及展示类型分别标注，只认官方证据。 |
| **李 `li` · 红框** | 1–3 篇；不凑数。周一另外单列 1 篇经典、综述或基础论文，不算当期新稿。 | 优先固定本体、映射、源模式下的 VKG/OBDA 实例更新、视图更新与双向变换、provenance/lineage/causality、副作用最小化及约束修复等。理论论文无代码不扣分。 |
| **驴 `lv` · 黑框** | 1–3 篇；周一可另加最多 1 篇经典、综述或重要方法。 | P0 机器人学习与操作；并列 P1 机器人感知、视觉与空间智能，以及仿真、Sim-to-Real、数据与评测；P2 VLA、世界模型、跨本体泛化、人形全身控制及灵巧操作。优先级不作配额。 |

- **迅的正式身份**：只计有官方证据的 accepted 或 published。按 schema 填 `formalPublication` 和对应官方来源；纯 arXiv、workshop、未核实稿不计配额。已获正式录用或发表可用 arXiv 原文链接，但 arXiv 更新日期不能当录用或发表日。新配额自 2026-11-06 起，不追改更早历史。
- **李的补足规则**：核心方向不足，才另筛近 30 天有可核实贡献或影响力的数据库论文，再按正式日期向前查漏。优先 SIGMOD/PACMMOD、VLDB/PVLDB、PODS、ICDT、ICDE、EDBT、TODS、VLDB Journal、TKDE；核心另看 ISWC、ESWC、KR、Semantic Web、JWS 等。拓展项标为“数据库拓展阅读”，讲清影响力证据以及与核心方向的关系，不强行套用。已读种子 *Minimizing Side-Effects in VKG Updates* 和 *Realizing Bidirectional Virtual Knowledge* 不当新发现。
- **驴的读法**：兼顾前沿与基础，讲清现在可读懂什么、缺什么前置知识、优先看哪些已核实的章节/图表。不把纯 CV 或 LLM 热文当机器人论文；CVPR、ICCV、ECCV 只选与机器人感知、操作、空间理解或具身任务直接相关的工作。
- **来源与去重**：完整来源以 `config/digest-rules.json` 和 `config/source-registry.json` 为准，不靠本手册里举的例子代替。优先检查上次成功以来未推内容，优质旧文可首次推荐但标明“旧文首次发现”。用 DOI / 无版本 arXiv ID 关联预印本和正式版；跨频道同一论文共用记录，分别写推荐理由；重大更新再推须写清变化。不重置稳定 ID。

## 3. 单篇卡片和素材怎么核验

- **写作字段**：双语标题、完整作者、日期、venue 和正式状态；100–200 字中文导读及忠实英文译文，交代问题、方法、结论、适用条件和局限。另填标签、难度、推荐理由、前置知识、阅读建议，以及代码、数据、项目或视频的查证结果。只读摘要就标明，不把作者报告写成独立复现。
- **李的额外信息**：区分来源恢复、方案生成、必要副作用、用户接受与正确性，说明关键假设与实验能支持什么；分开标注理论不支持、实现不支持和本轮未找到。
- **作者与机构**：以论文 PDF、HTML 署名或可证实本论文关系的官方项目为准，不由作者当前单位反推。每篇逐校查证；通过稳定机构 ID 和别名复用 `data/institutions.json` 中已有的真实标识、路径与 SHA256。
- **标识**：大学用真实独立校徽、盾徽或身份图形，其他机构用真实官方紧凑图形。40×32 CSS px 图盒，等比完整显示，机构名称另列。核验像素、透明度、出处、使用条件及派生记录；不把长字标缩小冒充校徽，不用 AI、近似图或随意首字母。缺失先查，仍无法核实时只留真实机构名，并登记已查入口和待核原因。透明优先；可靠去底要保留图内白色和原件，做不到则记录原生底色例外。
- **论文图与头像**：精选用真实论文或作者项目的主图、teaser 或方法图，保留比例和完整图意，写来源、图号、credit、替代文字及使用说明。无可用图的理论论文可留空。不造实验图、头像、认证或流量数据；用公开官方照片须能确认人物身份。素材来源可核验不等于拿到许可或得到机构背书。

## 4. 独立 arXiv 模块和科研日历

**迅的 arXiv 模块**：不占精选名额。逐页检查官方 `cs.RO`、`cs.CV`、`cs.LG`、`cs.AI`、`eess.SY`、`eess.IV`，合并 `cs.SY` 别名。保留全部符合范围的新稿和相关修订，记录交叉列表并按无版本 ID 去重；不设 Top N。非 RO 须直接关联机器人任务。保留批次、版本、分类、来源及覆盖状态；每篇有双语导读和机构核验，仅省略主图。无新公告保留上期的真实批次日期；访问失败或导读未完不记作 0 篇，也不写“全覆盖”。

**科研日历**：不新增独立定时任务。按三频道实际会议来源合并核验官方网站、CFP、Dates；记录登记、摘要、全文等不同阶段，分别标明受邀/普通投稿及补充材料。保留原时区、AoE、日期精度与稳定事件 ID；日期只精确到天，就不补小时。核实城市、国家、场馆；冲突列明来源并标待核，未公布或访问失败不猜日期，保留最后有效资料。即使没有合格论文也照常核验日历。只在重要变化或维护失败时在同一简报加一句。

## 5. 日常执行与发布验收

1. **读规则和基线**：`README.md`、`docs/DIGEST-INTERFACE.md`、`docs/CARD-ASSETS.md`、`docs/ARXIV-BULLETIN.md`、`docs/CONFERENCE-CALENDAR.md`、两份 `config/` 文件、当前 schema、`data/index.json`、`data/registry.json`、`data/institutions.json`、`data/arxiv/index.json`、`data/conference-calendar.json`。核实当前主分支 SHA 和已上线日期。检索、选文、arXiv 分页和日历可并行；支持档位时用中等思考做研究，不声称改变无法控制的档位。
2. **合并最小变更**：更新当期日报、索引、论文版本登记、必要素材或机构/地理记录、独立 arXiv 和日历。保留历史、蓝红黑频道边框、白蓝红磨砂界面和归档，不顺手改前端。迅的高达侧图、李的轮换照片保持原规则；不恢复闪烁或扫描动画。收藏、已读、笔记、私事只在浏览器本设备存储，保留原键及各自导入导出，不读取或上传。
3. **先验再发**：运行 `npm run check`，确认测试、schema 校验和构建全部通过；检查素材实际存在、哈希匹配、链接安全、配额和缺额说明、去重、各表引用和上期保留。素材上传不等于发布；大图先做可读的等比缩略，更新尺寸、哈希和派生说明。
4. **原子提交**：通过 GitHub 以最新 `main` 为父提交，把完整发布所需文件放在同一提交。更新分支用预期 SHA（`expected_sha`）防止覆盖并发更新；若主分支变了，重新对齐并重跑校验，不强制覆盖。已上传素材先核验可复用；失败或重跑保持幂等。
5. **线上验收**：确认对应提交的 Pages 工作流成功，再直接读取线上索引和本期数据，必要时抽查日历、arXiv 与素材。提交成功但 Pages 未核验，不能说已上线。成功后的一条中文简报写迅各配额实际数量、李/驴数量、少量重点和站点入口；可以补一句覆盖缺口或日历重要变化。失败保留上一版并说明卡在哪一步，不无限重试或重复通知。频道名不是通知收件人。
