# 零域 / ZERO FIELD

每日论文精选：白底、蓝色主色、红色点缀，无装饰动画。静态 HTML/CSS/JavaScript 与同源 JSON，无后端、登录、追踪器、外部字体/CDN 或浏览器端论文 API。

网站：https://gohmadein.github.io/academic-paper-radar/

首期为 **2026-10-31，11篇真实论文**：迅7、李2、驴2。9篇为近30日预印本，李的2篇是较早正式论文首次发现；不是近期新发表或周一经典。迅为摘要级导读，李/驴为正文重点核读。没有独立复现或完整证明复核。首期检索并未穷尽来源目录，具体边界在每期导读中显示。

## 本地检查与构建

Node.js 20+（CI为24），无需安装依赖、API密钥或系统软件。

```sh
npm run check
npm run preview
```

`check` 一次完成测试、资料校验、确定性静态构建。预览地址 `http://127.0.0.1:4173/academic-paper-radar/`。不能直接双击 HTML；本机开发服务器不作为生产后端。静态产物在 `dist/`，可托管在项目子路径或站点根路径。

## 导入新一期

先阅读 [输入接口](docs/DIGEST-INTERFACE.md)。英文/中文题名、作者、原文、发表身份必须核验。中文导读100–200个Unicode字符，不凭标题猜结果。未核验资源为null，不能猜项目/代码URL。每个非空资源需有对应证据条目。核验日期可保留到日，不捏造更精确时间。

```sh
npm run ingest -- normalized.json
npm run check
```

导入只接受完整日报v2，按 DOI / arXiv base / other 身份别名合并；同日跨类别重叠保留一个ID与各自推荐。已存在身份沿用原ID，预印本转正式版不破坏收藏。跨日普通重复推荐会被拒绝；实质更新须用 `major-update` 和具体 `updateNote`，经典用单独标记。历史日期保留当期快照。

导入器先在项目内临时目录准备完整数据集并校验，再替换数据目录，失败回滚。不要手改一个文件后就发布。**GitHub远端发布的原子性来自同一次Git提交/分支更新**；本机目录替换不等同于跨文件系统的数据库事务。候选临时目录在 `.gitignore` 中，提交只包含审核后的源文件。

仅生成可用于云端连接器的变更计划，不修改当前资料：

```sh
node scripts/ingest.mjs normalized.json --plan > commit-plan.json
```

计划的 `files` 含3个JSON文件的完整UTF-8内容与SHA256：当日日报、索引、注册表；`assetFiles` 含被引用图像的base64字节，需用create_blob建立二进制blob，再一并放入同一个树/提交。`commit-plan.json` 是临时工作文件，不需要公开提交。真实素材必须先放到规范本地路径并通过校验，不能依赖浏览器运行时访问外部图床。

## 无人值守的GitHub提交与Pages

搜集任务由外部云端调度负责；静态网站本身不运行搜集器。调度意图为2026-11-01起每天北京时间08:00，研究思考程度medium仅记录为操作意图，不声称仓库代码改变了模型/API设置。仓库不创建重复定时任务，不依赖桌面在线、电脑登录或本机gh。

云端执行者读取最新规则、索引与注册表，完成原始来源核验和规范JSON，再使用已授权的GitHub连接器：

1. 读取 `heads/main` 的当前SHA，读取该提交的tree SHA，作为本次基线。
2. 按导入器的计划，用 `create_tree(base_tree=基线tree)` 一次加入3个文件：`path`、`mode=100644`、`type=blob`、完整UTF-8 `content`。不逐个创建独立提交。
3. `create_commit(tree=新tree, parents=[基线SHA])`，消息注明日报日期与实际数量。
4. `update_ref(heads/main, sha=新提交, expected_sha=基线SHA, force=false)`。比较并交换失败时重新读取最新资料和注册表后重新规划，不能强制覆盖别人的更新。
5. 读回main确认SHA，检查该SHA的Pages工作流到成功；访问公开URL，并比对构建校验清单。工作流失败时旧站点继续保留，不能宣称新一期已上线。

这是一个原子Git提交，可完全从云端连接器完成，无需把凭据放入仓库。连接器通过正常授权用户/应用推送可触发 `push` 工作流；不要改用工作流内部的 `GITHUB_TOKEN` 推送后默认为它会自动触发下一次Pages构建。

`.github/workflows/pages.yml` 在main推送后测试、验证、构建并发布dist，Pages部署仅使用最小权限。每日内容流程不要修改其他源文件。调度和无人值守首次运行的实际验证由外部任务记录；页面上线不等于证明未来每次自动执行都成功。

### 阅读界面

桌面使用可收起的浅色侧栏和限宽阅读列。论文卡片左文右图，手机改为上下布局；中文／英文导读上下排列，各先显示两行，可原位展开完整内容。书签、已读、笔记与分享独立操作，不触发详情。导读展开仅在本次页面会话保留，书签／已读仍使用原本机存储键。详情与分享保留键盘关闭和原有公开链接格式。


### 本机论文笔记

每篇论文的操作栏有笔记图标；有内容时显示蓝色小点。详情也可打开同一篇的笔记。纯文本多行编辑，350 毫秒自动保存，关闭、切换和离开页面时再次保存；按稳定论文 ID 关联，方向、日期、书签和搜索视图共用同一份笔记。Esc／关闭／点弹窗外侧返回原操作位置。删除按钮需确认。

笔记使用独立键 `paper-signal-notes-v1`，只保存在当前浏览器，不上传、不追踪、不放入公开链接。清除浏览器数据会丢失笔记。保存失败会明确显示「尚未保存」，草稿仅保留在当前页面，须重试或导出备份；已有存储无法读取时不会覆盖原记录。检测到其他标签页改动时暂停写入，防止旧页面覆盖新记录；先导出本页草稿再重新加载。建议不要在多个标签页同时编辑笔记。

编辑器的「备份与迁移」可导出全部笔记或导入独立 `paper-signal-notes` v1 JSON，也可粘贴／复制 JSON。导入仅新增，完全相同内容去重，不同内容跳过并报告数量，保留本机版本；未知但有效的论文 ID 保留。原书签 `paper-signal-bookmarks` v1 格式与导入入口不变，两类备份互不混用。每篇最多 10000 个 UTF-16 字符，最多 5000 条，总 JSON 最多 2 MiB；浏览器实际存储配额可能更小。达到总量限制时仍保留当前会话草稿，可用「导出本篇」逐篇备份后整理。备份包含私人笔记，请勿公开上传。无后端或云同步。

### 迅页面磨砂背景

仅迅的真实每日推送页显示两幅淡色高达线稿。按最新界面要求，取消中央实白遮挡：图像固定于整个阅读区域下方的左右两半，分别裁切、不互相重叠，桌面避开侧栏，手机覆盖阅读视口；保留22%透明度和共享磨砂卡片，背景不接收点击、不自动移动，文字和操作始终在上层。窗口或侧栏尺寸变化时重新计算；其他方向、归档、书签、来源目录、演示、打印、减少透明度和强制颜色模式不显示。素材沿用用户提供模型照片的AI线稿转换，不新增图片，与论文插图和机构标识分开管理。

### 李页面照片与静态玻璃卡片

仅李的真实每日推送页使用用户指定的两张照片作固定阅读背景；照片不用于其他方向、来源目录、归档、书签、演示和打印。照片由同源、内容哈希命名的 WebP 提供，无 AI 改图，仅等比例优化和 CSS cover 裁切。72% 白色遮罩压低背景噪声，卡片使用半透明白底、背景模糊、细高光和红色方向边框；论文插图及操作按钮仍有清晰底色。不支持背景模糊时卡片回退为实白底；系统要求减少透明度或强制颜色时隐藏照片并取消玻璃。

轮换按**最新成功发布的数据集合**，不按设备时钟或当前筛选日期：2026-11-01 为第一张锚点，`lib/li-background.js` 对此日期之后的不同真实日报日期计数，奇数用第二张、偶数用第一张。新一期（即使间隔多天）切换一次；同日重发、刷新、切换历史日期或搜索均不切换。较早历史补录不影响轮换。完整历史索引须保留；如未来裁剪历史，需同时迁移锚点/计数。没有自动播放、计时切图、随机选择或新增本机状态。

### 共享磨砂玻璃与圆角机构库

全部方向、迅、李、驴的真实每日推送共用静态半透明磨砂卡片（18px背景模糊、白色高光），保留各方向蓝／红／黑边框。机构标识库的外容器统一16px圆角及内边距，推送页也采用同样磨砂底；内部机构卡片和标志本身不裁切、不额外磨糊。其他视图只更新外容器圆角，保持普通可读底色。

李的照片和按日报轮换逻辑不变；迅的高达以22%透明度固定在磨砂阅读区域下方，按最新要求不再局限外侧留白；驴与全部方向不新增背景图片。因此无照片页面的玻璃视觉更克制。无背景模糊支持／减少透明度／强制颜色／打印时均保留清晰实底回退。不改变笔记、书签、已读或论文ID。

### 驴的会议、期刊与 arXiv 补充

会议目录含 CoRL、RSS、ICRA、IROS，**仅机器人学习相关**的 NeurIPS、ICLR、ICML，以及**仅机器人感知／操作／空间理解／具身任务直接相关**的 CVPR、ICCV、ECCV；期刊目录含 RA-L、T-RO。arXiv 配置关注 cs.RO 和**仅与机器人任务直接相关**的 cs.LG、cs.CV，不增加第四个侧栏菜单。原有7组团队不变。
