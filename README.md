# 研究信号 · PAPER SIGNAL

中文学术论文每日精选阅读站。赛博朋克风格：`#0a0a0f` 深色画布，`#00f0ff` 青色、`#ff0080` 洋红、`#ffe600` 黄色 HUD；手机与桌面自适应。

**纯静态前端、零第三方依赖。** HTML / CSS / 原生 JavaScript + 随站点发布的 JSON。没有后端、数据库、登录、追踪器、外部字体/CDN 或浏览器端论文 API。

当前真实论文收录为 **0**。研究方向和筛选要求尚未设定。首页默认显示真实内容；点击「探索演示版」可查看明确标记为「演示数据，非真实论文」的虚构占位条目。演示条目不含虚构引文、真实作者冒用或编造的实验结果，不计入真实统计。

## 本地使用

需要 Node.js 20 或以上，无需 `npm install`。

```sh
npm run validate
npm test
npm run build
npm run preview
```

打开终端输出的本地地址（默认 `http://127.0.0.1:4173/academic-paper-radar/`）。不能直接双击 `index.html`：浏览器的 `file://` 安全限制不支持本项目所需的模块与 JSON 请求。本地预览脚本只用于开发，绑定本机地址，不作为生产后端部署。

## 阅读功能

- 关键词搜索：标题、中英文标题、作者、发表载体、中文导读、入选理由、主题。
- 主题与日期组合筛选、日期归档、无结果状态、资料读取失败重试。
- 论文详情弹窗、来源外链与明确的外部站点提示。
- 本机书签：保留原有 `localStorage` 键；真实与演示视图分开显示，清除浏览器数据后消失。支持 JSON 导出/导入手动跨设备迁移，合并去重并保留已有条目。当前云端尚未连接，不声称自动同步。存储不可用时退回当前会话并提示。
- 每日精选首页的右侧 HUD：完整斜角轮廓霓虹边框、CSS clip-path 标题 glitch、全页非交互扫描线。翻页计数器来自真实/演示档案实际数量，不生成虚构活动；本机时钟与六边形状态面板已按要求移除。归档与本机书签页隐藏整个首页介绍区与顶部演示横条，不留占位；演示档案仍保留行内提示及卡片标记。尊重减少动态效果设置。
- JetBrains Mono 官方 WOFF2 随站点自托管，许可证见 `assets/fonts/OFL.txt`。该字体不包含中文；所有文本优先声明 JetBrains Mono，中文由设备 PingFang SC / Microsoft YaHei / 系统字体补齐，没有 Google Fonts/CDN 请求。
- URL hash 保留当前视图、搜索、主题、日期与详情；可复制当前网址分享。浏览器前进/后退可恢复视图。
- 键盘导航、可见焦点、跳过导航、按 `/` 聚焦搜索、`Esc` 关闭详情、尊重系统减少动态效果设置。

## 每日新增资料

1. **先确认筛选规则。** 例如研究主题、关键词、排除项、时间范围、来源、同行评审/预印本范围、每天篇数和推送时间。本项目没有预设这些要求。
2. 创建日期文件及索引：

   ```sh
   npm run new-day -- 2026-11-01
   ```

   命令只生成空日报，不搜集或杜撰论文，遇到已有日期立即停止。日期代表收录日；采用的时区需另行约定。
3. 从 `templates/paper.json` 复制对象到当天 `papers` 数组；用**经核实的真实信息**替换所有占位字段。`sources` 至少一个原始来源，支持 HTTPS/HTTP，不允许带用户名/密码的链接。建议 HTTPS；标明预印本是否未经同行评审。阅读原文或摘要后编写导读，不推断未核实结果。
4. 同步 `data/index.json` 对应日期的 `count` 与 `title`，索引建议按日期倒序。每个论文 `id` 必须稳定且在真实档案中全局唯一；同一论文再次出现请更新原记录或明确不同版本并解释。
5. 执行 `npm run validate`、`npm test`、`npm run build`。本地预览确认后提交源码并重新部署。不要手工编辑生成的 `dist/`。

索引示例：

```json
{
  "version": 1,
  "days": [
    {
      "date": "2026-11-01",
      "file": "days/2026-11-01.json",
      "count": 0,
      "title": "2026-11-01 论文精选"
    }
  ]
}
```

日报结构：

| 字段 | 说明 |
| --- | --- |
| `version` | 固定为 `1` |
| `date` | 有效 `YYYY-MM-DD`，与文件名及索引一致 |
| `title` | 当天主题标题，与索引一致 |
| `demo` | 真实目录必须 `false`，演示目录必须 `true` |
| `papers` | 论文对象数组；允许空数组，不产生虚假精选 |

论文结构：

| 字段 | 说明 |
| --- | --- |
| `id` | 必填，小写字母、数字、短横线，最多 100 字符 |
| `title` / `titleEn` | 必填标题 / 可选原始英文标题 |
| `authors` | 非空作者字符串数组 |
| `year` | 1800–2200 的整数发表年份 |
| `venue` | 发表载体及必要的预印本说明 |
| `tags` | 非空主题字符串数组 |
| `summary` | 中文导读：问题、方法、主要发现、条件与局限 |
| `whySelected` | 依据筛选规则说明入选理由 |
| `sources` | `[{"label":"论文原文","url":"https://..."}]`，真实论文不得为空 |
| `demo` | 真实论文为 `false` |
| `notice` | 仅演示条目需为 `演示数据，非真实论文` |

`schema/` 可用于编辑器辅助。无需下载 Schema 即可使用脚本；离线校验器执行关键类型、真实日期、目录身份、来源协议、重复 ID、索引与文件一致性等检查。程序校验不能证明论文事实或筛选质量，内容仍需人工核验。文本按纯文本转义渲染，不执行内容中的 HTML/Markdown。

## 静态部署

构建命令 `npm run build`，发布目录 **`dist/`**。把该目录完整内容上传到任何支持 HTTPS 的静态主机即可。不需要 Node.js 常驻、服务端函数、环境变量、密钥或数据库。使用相对资源路径，支持域名根目录或 `/academic-paper-radar/` 等项目子目录；详情与筛选使用 hash，不需要服务器重写规则。

构建仅复制白名单页面、资源、脚本与数据，不包含开发脚本、模板、测试或本机配置。每次构建生成可复核的 SHA-256 `checksums.txt`；相同源码产生相同文件。建议 HTML/JSON 使用短缓存或协商缓存，避免只更新索引而日报文件仍旧；每次发布完整替换产物。仓库公开后，不要提交未公开论文全文、密钥或私人信息。

### GitHub Pages（免费试运行）

仓库的 `Settings → Pages` 选择 **GitHub Actions** 作为发布来源。附带的 `.github/workflows/pages.yml` 在推送到 `main` 时先执行测试与校验，再将同一提交构建的 `dist/` 发布至 Pages。首次启用 Pages 需要仓库管理权限；流水线没有定时触发器、第三方 Action、账户密钥或搜集任务。工作流仅使用 GitHub 官方 Actions，部署任务只获得 Pages 和 OIDC 所需权限。

仓库公开和启用 Pages 后，实际可用网址应以 GitHub Pages 部署成功返回的 URL 为准。**免费 GitHub Pages 不能保证大陆每个地区、运营商与时段均可访问。** 本项目没有接入大陆多线路实测。若未来需要大陆稳定性承诺，需另行选择符合相关要求的托管、域名及必要手续；纯前端架构仍可沿用。

也可在普通静态主机使用同样的 `dist/`；不要把 `scripts/serve.mjs` 当生产服务。

## 本机书签跨设备迁移

1. 在电脑打开「本机书签」，点击「导出 JSON」，保存 `paper-signal-bookmarks-日期.json`。
2. 通过你自己的文件传输方式把 JSON 发送到另一台设备；本站不会代传或上传这些文件。
3. 在手机打开相同网站的「本机书签」，点击「导入 JSON」，从系统文件选择器选择文件。iPhone 可先把文件存到“文件”App，再在 Safari 的文件选择器中选取。
4. 页面报告新增、已有与未收录 ID 数量。重复导入不会新增重复条目；原有书签保留。真实与演示书签仍分开显示。

如果浏览器未显示下载，可展开「下载未出现？查看并复制 JSON」，将完整内容带到另一台设备的「也可粘贴 JSON 导入」。文件导入与粘贴导入使用同一校验和合并逻辑。

文件格式为 `{ "format": "paper-signal-bookmarks", "version": 1, "exportedAt": "ISO UTC 时间", "ids": ["论文稳定ID"] }`。导出只包含 ID，不包含来源 URL、账户或凭据。导入最多 256 KB、5000 条；拒绝错误版本、损坏 JSON、不合法 ID 和多余字段（包括链接/脚本）。无效导入或存储失败不会覆盖原有收藏。未收录 ID 会保留，方便不同日期或版本间迁移。

用户已允许后端自动同步，当前正在等待实际项目/所有者/登录配置验证。隔离接口 `lib/bookmark-sync.js` 与 `backend/schema-draft.sql` 尚未连接页面；当前 `connect-src 'self'` 阻止外部 API 请求。不能把手动 JSON 迁移称为自动同步，不能自动公开旧本机数据。后端配置与验收条件见 `backend/README.md`。

## 每日推送与前端的边界

这里实现的是**读取已提交资料的静态阅读站**。目前没有每日论文搜集器、AI 调用、订阅通知或自动写仓库的定时任务。

将来的任务应独立运行于你的电脑、CI 或其他经授权的执行环境：依据已确定的标准搜集 → 核验来源和结论 → 写入日期 JSON 与索引 → 通过校验 → 提交仓库 → 静态重新部署。浏览器只读取同源文件。只有先确定来源、筛选要求、频率和运行权限后，才另行实现调度；不要把 API 密钥放到前端仓库中。

## 验证与限制

`npm test` 使用 Node 内置测试框架，无第三方包。涵盖日期边界、来源协议、HTML 转义、组合筛选、路由参数、损坏书签、真实/演示分离、索引完整性和外部运行时资源检查。浏览器检查记录见 `QA.md`。

数据在页面加载时整体读取，适合早期轻量档案；资料量很大后可改为按日期分段加载，保持纯静态架构。没有离线 Service Worker；刷新页面需要连接静态主机。移动端需要支持现代 JavaScript、Fetch 和原生 `dialog` 的浏览器。正文网页和原文来源外链的可访问性是两个独立问题。
