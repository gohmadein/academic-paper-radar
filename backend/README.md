# 后端连接草案：尚未连接，尚未启用同步

当前线上书签仍为本机存储。此目录与 `lib/bookmark-sync.js` 只提供隔离的 Supabase 接口与迁移草案，不会创建服务、读取凭据、注册用户、上传旧书签或发起外部请求。页面没有导入这个适配器，也没有“已同步”提示。

拟议行为：公开共享阅读清单所有人可读；只有经管理员核实、加入保护白名单的单一所有者可以增删。现有本机书签保持私有，需要另行明确点击确认才能迁移为公开条目。实际接口成功并读回确认后，页面才可显示云端保存成功；网络失败不得提前标记同步。

## 仍需真实配置与确认

1. 用户授权连接或创建的免费 Supabase 项目、项目 URL、publishable 公钥；不接受 secret/service_role 或数据库密码进入前端。
2. 管理员核实真正所有者的 `auth.users.id`，执行 SQL 迁移，再单独加入 `private.paper_signal_owners`。不能由首位访问者、自助注册或用户可编辑元数据决定所有者。
3. 实际登录方式与允许回调地址。应关闭开放注册；所有者密码/验证码在可信登录 UI 中由用户输入，不能发在聊天或提交仓库。Supabase 默认 SMTP 仅向项目团队邮箱投递，通常每小时 2 封且为 best-effort，不应承诺通用邮箱魔法链接开箱即用。见 [Supabase SMTP 文档](https://supabase.com/docs/guides/auth/auth-smtp)。
4. 前端 CSP 只在已确认项目时增加该项目 API 域名；当前仍限制 `connect-src 'self'`，不会误连外部服务。自托管前端不等于大陆网络可稳定连接海外后端，需单独实测。

## SQL 与权限验收

`schema-draft.sql` 是全新专用项目中的模式设计草案，尚未执行，不是已生成的迁移记录；实际连接后按 Supabase 工具流程生成迁移并运行 Advisors。不能在未核验的旧数据库上重复执行。不存在自动生成/争抢所有者的逻辑。前端只需要公开公钥；RLS 是真正的写权限边界。匿名与普通登录用户不可写入，所有人只读公开清单；没有 UPDATE 授权。唯一的 SECURITY DEFINER 检查函数位于非公开 `private` schema，公开 RPC 仅为 SECURITY INVOKER 包装。

连接后必须在真实项目完成以下验收，不能用代码静态检查或 mock 测试代替：

| 身份 | 读取 | 添加/删除 | 修改 owner 白名单 |
| --- | --- | --- | --- |
| 未登录，publishable 公钥 | 成功 | 拒绝 | 拒绝 |
| 已登录但非所有者 | 成功 | 拒绝或影响 0 行 | 拒绝 |
| 管理员核实的所有者 | 成功 | 成功并读回确认 | 拒绝 |

还需验证伪造可编辑用户元数据、不同 JWT、重复添加、断网/超时、登录过期、第二台设备读取、退出登录、从本机到公开清单的明确确认流程。禁止未经许可创建测试账号。删除 RLS 策略可能返回 0 行而非 403，所以适配器始终读回检查最终状态。

`lib/bookmark-sync.js` 的 mock 测试仅验证请求、错误处理与成功确认契约；当前没有真实数据库、身份认证或 RLS 实测结果。完成以上配置前，可独立发布视觉与本机书签导入/导出，不能声称自动同步已完成。
